🥑 GenUI Flow: Complete Walkthrough

Example: "Suggest a healthy breakfast"

Let's follow exactly what happens when a user asks for breakfast suggestions

Using GenUI SDK's Default Catalog
(card, column, text, button, image, etc.)

📚 Understanding the Catalog

What is a Catalog?

A Catalog is a collection of pre-defined widgets that the AI can use to build UIs. GenUI SDK comes with 18 built-in catalog items (widgets) that cover most common UI needs.

GenUI SDK's Default Catalog Items:

// From GenUI SDK source code: static Catalog asCatalog() { return Catalog([ audioPlayer, // Play audio files button, // Clickable buttons card, // Material card wrapper checkBox, // Checkbox input column, // Vertical layout dateTimeInput, // Date/time picker divider, // Visual separator icon, // Material icons image, // Display images list, // Scrollable list modal, // Dialog/popup multipleChoice,// Radio buttons/chips row, // Horizontal layout slider, // Value slider tabs, // Tab navigation text, // Display text textField, // Text input video, // Video player ]); }

How It Works:

  • You provide the catalog to GenUiConversation when initializing
  • AI sees the catalog and knows which widgets it can use
  • AI composes UIs by combining these catalog items
  • SDK builds widgets using the catalog item's builder function

💡 Key Point: In this example, we're using GenUI's default catalog items.
The AI combines card, column, and text to build the breakfast UI.
No custom widgets needed!

1

User Types Message

User opens the app and types: "Suggest a healthy breakfast"

In your Flutter code, when user presses send:

Your Flutter Code
// In your ChatScreen.dart // Step 1: Initialize GenUiConversation with the default catalog final _genUiConversation = GenUiConversation( contentGenerator: myContentGenerator, catalog: CoreCatalog.asCatalog(), // ← The 18 built-in widgets! ); // Step 2: Send user message void _sendMessage() { final text = _textController.text; // "Suggest a healthy breakfast" // Send to GenUiConversation _genUiConversation.sendRequest( UserMessage([TextPart(text)]) ); }
📌 What Happens Here:

• You initialized GenUiConversation with CoreCatalog.asCatalog()

• This gives AI access to 18 built-in widgets (card, column, text, etc.)

• Your app wraps user text in a UserMessage object

• Sends it to GenUiConversation (the mediator)

• GenUiConversation adds it to conversation history

Message Format Sent:

JSON
{ "parts": [ { "text": "Suggest a healthy breakfast" } ], "role": "user" }
⬇️
2

AI Returns Component Structure

GenUiConversation forwards the message to ContentGenerator, which talks to Google AI.

Important: ContentGenerator also sends the catalog schema to AI, so AI knows which widgets it can use!

What Gets Sent to AI
{ "systemInstruction": "You're a helpful assistant...", "tools": [ { "name": "card", "schema": {/* Card widget properties */} }, { "name": "column", "schema": {/* Column widget properties */} }, { "name": "text", "schema": {/* Text widget properties */} }, // ... all 18 catalog items ], "messages": [ { "role": "user", "text": "Suggest a healthy breakfast" } ] }

AI thinks: "User wants breakfast. I can use the card, column, and text catalog items to build a nice breakfast UI!"

AI returns a function call named surfaceUpdate:

AI Response

🎯 Key Points:

• surfaceId: "breakfast_healthy_1" - unique identifier for this UI surface

• components: Array of 8 UI components (1 Card, 1 Column, 6 Text widgets)

• id: Each component has unique ID like "card_avocado_toast"

• component: Uses catalog item names: "Card", "Column", "Text"

• Hierarchy: Card → Column → Text widgets (from default catalog)

• AI chose these: From the 18 available catalog items!

💡 Why This Structure?

AI is composing a widget tree using the catalog items you provided!

• Card catalog item - wraps content in Material card

• Column catalog item - arranges children vertically

• Text catalog item - displays text with styling

Just like you would write: Card(child: Column(children: [Text(...), Text(...)]))

But AI sends it as JSON structure using catalog item names.

3

GenUiManager Stores in DataModel

The GenUiManager receives the surfaceUpdate function call and processes it.

What happens in the logs:

Console Logs
[FINE] Processing function call: surfaceUpdate with args: Struct() [FINE] Invoking tool: surfaceUpdate [FINE] Adding new surface breakfast_healthy_1 [INFO] Adding surface breakfast_healthy_1 [INFO] Invoked tool surfaceUpdate with args { components: [ {id: card_avocado_toast, component: {Card: {...}}}, {id: column_avocado_toast, component: {Column: {...}}}, {id: title_avocado_toast, component: {Text: {...}}}, // ... all other components ], surfaceId: breakfast_healthy_1 } Result: { surfaceId: breakfast_healthy_1, status: "UI Surface breakfast_healthy_1 updated." }
📦 What's Being Stored:

• GenUiManager stores all components in the DataModel

• Key is the surfaceId ("breakfast_healthy_1")

• Value is the complete component tree structure

DataModel Structure After Storage:

DataModel Contents

DataModel = { "breakfast_healthy_1": { "components": { "card_avocado_toast": { "Card": { "child": "column_avocado_toast" } }, "column_avocado_toast": { "Column": { "alignment": "start", "children": { "explicitList": [ "title_avocado_toast", "desc_avocado_toast", "time_avocado_toast", "ingredients_header", "ingredients_list", "nutrition_avocado_toast" ] } } }, "title_avocado_toast": { "Text": { "text": {"literalString": "Avocado Toast with Poached Eggs"}, "usageHint": "h2" } }, "desc_avocado_toast": { "Text": { "text": {"literalString": "A nutritious breakfast..."}, "usageHint": "body" } }, // ... all other components stored here } } }
🔍 Understanding DataModel:

• Think of it as a database/storage for UI components

• Each surface has its own entry (key = surfaceId)

• All components are stored with their IDs and definitions

• Widgets can look up any component by ID anytime

  • Surface ID: "breakfast_healthy_1" - Acts as the main key
  • Components Map: All 8 components stored with their IDs
  • Relationships Preserved: Card references Column by ID, Column lists Text widget IDs
⬇️
4

beginRendering Triggers Build

After storing components, AI calls another function: beginRendering

AI's Second Function Call
FunctionCall( name: "beginRendering", args: { "root": "card_avocado_toast", "surfaceId": "breakfast_healthy_1" } )
🎬 What This Does:

• root: "card_avocado_toast" - Start building from this component

• surfaceId: "breakfast_healthy_1" - Which surface to render

• This tells the SDK: "Everything is ready, start building widgets!"

What happens in the logs:

Console Logs
[FINE] Processing function call: beginRendering with args: Struct() [FINE] Invoking tool: beginRendering [FINE] Fetching surface notifier for breakfast_healthy_1 [INFO] Started rendering breakfast_healthy_1 [INFO] Invoked tool beginRendering with args { root: card_avocado_toast, surfaceId: breakfast_healthy_1 } Result: { status: "Surface breakfast_healthy_1 rendered and waiting for user input." }
🚀 Behind the Scenes:

• GenUiManager finds the surface notifier for "breakfast_healthy_1"

• Triggers a rebuild of the GenUiSurface widget

• GenUiSurface will now start building Flutter widgets from the DataModel

  • Surface Notifier: A listener that tells Flutter "Hey, UI needs to update!"
  • Root Component: Starting point for building the widget tree
  • Ready State: All components are stored, now time to render them
⬇️
5

GenUiSurface Builds Flutter Widgets

Now the GenUiSurface widget starts building actual Flutter widgets from the component definitions in DataModel.

🔨 Build Process Explained:

1. GenUiSurface looks up "breakfast_healthy_1" in DataModel

2. Finds root component ID: "card_avocado_toast"

3. Creates Flutter Card widget

4. Card references "column_avocado_toast" as child

5. Creates Flutter Column widget

6. Column lists 6 children IDs

7. Creates each Text widget in order

8. Each Text subscribes to its data value

What "DataContext.subscribeToValue" means:

📊 Data Subscription:

• Each widget subscribes to its data in the DataModel

• If data changes later, the widget automatically rebuilds

• This is how reactive updates work in GenUI

• Similar to setState() or StreamBuilder in Flutter

The final Flutter widget tree that gets created:

Equivalent Flutter Code
// This is what GenUiSurface builds (conceptually) Card( child: Column( crossAxisAlignment: CrossAxisAlignment.start, children: [ Text( "Avocado Toast with Poached Eggs", style: Theme.of(context).textTheme.headline2, ), Text( "A nutritious breakfast with healthy fats and protein", style: Theme.of(context).textTheme.bodyText1, ), Text( "Prep Time: 5 mins | Cook Time: 10 mins", style: Theme.of(context).textTheme.caption, ), Text( "Key Ingredients:", style: Theme.of(context).textTheme.headline5, ), Text( "- Whole grain bread\n- Ripe avocado\n- Fresh eggs\n- Cherry tomatoes\n- Salt and pepper", style: Theme.of(context).textTheme.bodyText1, ), Text( "Approx. 350 calories, 18g protein, 20g healthy fats", style: Theme.of(context).textTheme.bodyText1, ), ], ), )
✨ The Magic:

• AI designed this widget tree using catalog items (card, column, text)

• Each catalog item has a builder function that creates the actual Flutter widget

• GenUI SDK calls the builder: cardCatalogItem.builder(data)

• Builder returns: Card(child: ...) (actual Flutter widget)

• No custom Dart code from you needed - catalog items handle everything!

🎯 Complete Flow Summary

Step 1: User Input

User types "Suggest a healthy breakfast" → Wrapped in UserMessage → Sent to GenUiConversation

Step 2: AI Response

AI returns surfaceUpdate with complete component tree (Card, Column, Text widgets) in JSON format

Step 3: Storage

GenUiManager stores all components in DataModel under surfaceId "breakfast_healthy_1"

Step 4: Trigger Render

AI calls beginRendering with root "card_avocado_toast" → Triggers GenUiSurface rebuild

Step 5: Build Widgets

GenUiSurface builds Flutter widgets from DataModel → Card → Column → 6 Text widgets → UI appears!

💡 The Key Insight

You provide the catalog (18 built-in widgets: card, column, text, button, etc.)
AI is the UI architect. It picks and combines catalog items to build UIs.
GenUI SDK is the builder. It calls catalog item builders to create Flutter widgets.
No custom widgets needed! The default catalog covers most use cases.
