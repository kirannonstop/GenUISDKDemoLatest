🎨 Understanding GenUI Flow

📚 Key Concepts First

Before we dive into the flow, let's understand the main players:

🎯 GenUiConversation
Role: The Mediator
Job: Sits between user and AI, manages the entire conversation
Does: Takes user input → Sends to AI → Receives A2uiMessage → Updates UI
🔌 ContentGenerator
Role: AI Provider Connector
Job: Talks to Google AI / Firebase AI
Does: Converts user messages to AI format, converts AI responses to A2uiMessages
📨 A2uiMessage
What: A message from AI to UI
Contains: Instructions like "Create a RecipeCard widget with this data"
Example: { surfaceId: "recipe_1", component: "RecipeCard", data: {...} }
💾 DataModel
What: A storage/database for UI state
Stores: All surface data like { "recipe_1": {component: RecipeCard, data: {...}} }
Why: So widgets can access their data anytime
🪪 Surface ID
What: A unique identifier for each UI widget
Example: "recipe_breakfast_1", "timer_step2"
Why: So we can find and update specific widgets in the DataModel
🎭 GenUiManager
Role: The State Manager
Job: Manages DataModel, handles A2uiMessages
Does: Receives A2uiMessage → Stores in DataModel → Tells widgets to rebuild

🔄 Who Understands What?

👤 User writes: "Suggest a healthy breakfast"
→ GenUiConversation understands this
→ Wraps it in UserMessage and sends to ContentGenerator
🤖 AI returns: JSON with tool calls
→ ContentGenerator understands this
→ Converts to A2uiMessage and sends to GenUiConversation
📨 A2uiMessage: { surfaceId, component, data }
→ GenUiManager understands this
→ Stores in DataModel using surfaceId as key
→ Tells GenUiSurface to rebuild
🎨 GenUiSurface looks for: surfaceId "recipe_1"
→ Reads from DataModel["recipe_1"]
→ Finds component name "RecipeCard" and data
→ Calls your widgetBuilder to create the widget

📖 The Complete Flow Example

1
👤 User Types Message

What happens: User types "Suggest a healthy breakfast" and clicks Send

// In your ChatScreen void _sendMessage() { final text = "Suggest a healthy breakfast"; // Send to GenUiConversation _genUiConversation.sendRequest( UserMessage([TextPart(text)]) ); }

Result: Message goes to GenUiConversation (the mediator)

⬇️
2
🎯 GenUiConversation (Mediator) Processes

What happens: GenUiConversation adds message to history and forwards to AI provider

// Inside GenUiConversation Future sendRequest(UserMessage msg) { // Add to conversation history _history.add(msg); // Forward to ContentGenerator (AI connector) await contentGenerator.sendRequest( conversation: _history, tools: _genUiManager.getTools() // Your catalog ); }

Key Point: GenUiConversation is the mediator between user and AI. It doesn't talk to AI directly - it uses ContentGenerator!

⬇️
3
🔌 ContentGenerator Talks to AI

What happens: ContentGenerator sends everything to Google AI / Firebase AI

// ContentGenerator sends to AI: { systemInstruction: "You're a cooking assistant...", tools: [ { name: "RecipeCard", schema: {...} }, { name: "IngredientChecklist", schema: {...} } ], messages: [ { role: "user", text: "Suggest a healthy breakfast" } ] }

AI thinks: "User wants breakfast. I should create a RecipeCard widget!"

⬇️
4
🤖 AI Returns Response

What happens: AI returns tool calls (widget creation instructions)

// AI returns (simplified): { "tool_calls": [{ "function": { "name": "create_component", "arguments": { "component": "RecipeCard", "surfaceId": "recipe_breakfast_1", // ← Unique ID "data": { "dishName": "Avocado Toast", "prepTime": 5, "cookTime": 10, "ingredients": ["eggs", "avocado", "bread"], "calories": "350" } } } }] }

Note: AI creates a unique surfaceId for this widget

⬇️
5
📨 ContentGenerator Creates A2uiMessage

What happens: ContentGenerator converts AI response to A2uiMessage

// ContentGenerator creates: A2uiMessage( surfaceId: "recipe_breakfast_1", componentName: "RecipeCard", data: { "dishName": "Avocado Toast", "prepTime": 5, // ... all the recipe data } ) // Emits on stream → GenUiConversation receives it

Who understands A2uiMessage? GenUiManager! GenUiConversation forwards it there.

⬇️
6
💾 GenUiManager Stores in DataModel

What happens: GenUiManager processes A2uiMessage and updates DataModel

// GenUiManager.handleMessage(): void handleMessage(A2uiMessage msg) { // Store in DataModel using surfaceId as key _dataModel[msg.surfaceId] = { 'component': msg.componentName, // "RecipeCard" 'data': msg.data // {dishName: "Avocado Toast", ...} }; // Trigger onSurfaceAdded callback onSurfaceAdded(SurfaceAdded(msg.surfaceId)); // Notify widgets to rebuild notifyListeners(); }

DataModel now contains:

DataModel = { "recipe_breakfast_1": { component: "RecipeCard", data: {dishName: "Avocado Toast", prepTime: 5, ...} } }
⬇️
7
📱 ChatScreen Adds Message to UI

What happens: The onSurfaceAdded callback triggers in your ChatScreen

// In your ChatScreen: void _handleSurfaceAdded(SurfaceAdded surface) { setState(() { // Add new message with the surfaceId _messages.add( MessageController(surfaceId: "recipe_breakfast_1") ); }); } // ListView rebuilds and shows: ListView.builder( itemBuilder: (context, index) { return MessageView( _messages[index], _genUiConversation.host ); } )
⬇️
8
🎨 GenUiSurface Renders Widget

What happens: GenUiSurface looks up the surfaceId in DataModel

// Inside MessageView/GenUiSurface: GenUiSurface( surfaceId: "recipe_breakfast_1", host: _genUiConversation.host ) // GenUiSurface does: 1. Look up "recipe_breakfast_1" in DataModel 2. Find: component = "RecipeCard", data = {...} 3. Find RecipeCard in catalog 4. Call: recipeCardCatalogItem.widgetBuilder(context) 5. Pass the data to your RecipeCard widget

Your widget appears!

⬇️
9
🔄 User Clicks Button (The Loop!)

What happens: User clicks "Get Recipe" button

// In your RecipeCard: ElevatedButton( onPressed: () => context.dispatchEvent('get_recipe'), child: Text('Recipe') ) // This triggers: context.dispatchEvent('get_recipe') ↓ GenUiSurface captures event ↓ Forwards to GenUiManager ↓ GenUiManager creates new UserMessage: UserMessage([ TextPart("User clicked 'get_recipe' on Avocado Toast"), DataPart(currentDataModel) // Current state ]) ↓ Back to Step 2! (GenUiConversation processes it)

The cycle repeats! AI receives the event, responds with detailed recipe, UI updates again!

🎯 Summary: The Key Players

🎯 GenUiConversation: The mediator/orchestrator. Manages the entire conversation loop.

🔌 ContentGenerator: The AI provider connector. Talks to Google AI/Firebase AI.

💾 GenUiManager: The state manager. Handles A2uiMessages and manages DataModel.

📨 A2uiMessage: AI's instructions to create UI. Only GenUiManager understands it.

🗄️ DataModel: Storage for all UI state, indexed by surfaceId.

🪪 surfaceId: Unique ID for each widget (like "recipe_breakfast_1").

🎨 GenUiSurface: Widget that renders by looking up surfaceId in DataModel.
